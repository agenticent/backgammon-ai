# Bug log

| Bug | Found by | Root cause | Fix | Test added |
| --- | --- | --- | --- | --- |
| Equivalent legal move orders rejected: with one White checker on 13 and dice `[2, 1]`, `13→12→10` was refused while `13→11→10` was accepted | Devin Review on PR #2 | `isLegalSequence` matched submitted moves against `generateMoveSequences`, whose output is deduplicated by final position, so only one ordering per outcome survived | `isLegalSequence` replays the submitted moves against `generateSingleMoves` and enforces the maximum-dice and larger-die rules independently, via the new `maxPlayableDice` | `moves.test.ts` — "accepts either order of the dice when both orders are legal", "rejects a sequence that reuses a die it does not have" |
| Incorrect hit metadata accepted: a move onto an opposing blot was accepted with `hit: false` | Devin Review on PR #2 | Sequence comparison checked `from`, `to` and `die` but never `hit` | Replay compares the submitted move's `hit` against the generated move's | `moves.test.ts` — "rejects a sequence that misreports a hit" |
| Black occupied points returned in reverse home order | Devin Review on PR #2 | `occupiedPoints` returned ascending point numbers, which is nearest-home-first only for White | Results are sorted by `distanceFromPoint`, so both players get nearest-home-first | `board.test.ts` — "lists occupied points nearest to home first for both players" |
| Simultaneous winners deserialize: a state with 15 checkers off for both players was accepted, and `winner` reported White because it is checked first | Devin Review on PR #2 | `deserializeGameState` validated each player's checker total independently, and 15 borne off is individually valid for either side | Deserialization rejects a state where both trays hold all 15, since a game ends the moment one player bears off the fifteenth | `serialization.test.ts` — "rejects a position where both players have borne everything off" |
| Blot exposure checked combination-shot blockers on mirrored points: with White's blot on 18 and made points 13–17, a lone Black shooter on 12 was scored 17/36 instead of 11/36 | Devin Review on PR #3 | `canHitWithRoll` measured intermediate landings in the opponent's distance coordinates but `isBlockedAtDistance` converted them with the evaluated player's `pointFromDistance` | Intermediate landings are resolved with the shooter's coordinate system | `evaluation.test.ts` — "only counts blockers in the shooter's path for combination shots" |
| Storage failures crashed the app while loading or saving a session | Devin Review on PR #4 | Storage API access was unguarded, and reading `globalThis.localStorage` could itself throw a `SecurityError` | Resolve default storage defensively and swallow storage read, write, and removal failures | `session.test.ts` — "returns null when storage is unavailable", "swallows storage write failures"; `App.test.tsx` — "renders the start screen when storage is unavailable" |
| Inconsistent restored sessions crashed when an invalid turn was completed | Devin Review on PR #4 | Session deserialization validated game states independently without checking that `turnMoves` replayed from `turnStart` to `state` | Reject partial AI turns and replay every saved human move, requiring the resulting state to match | `session.test.ts` — "rejects a session whose state does not match turnStart plus turnMoves", "rejects partial moves on the AI's turn", "round-trips a consistent mid-turn session"; `App.test.tsx` — "falls back to the start screen for an inconsistent saved session" |
| `storage={null}` still used `localStorage`, so the explicit persistence opt-out restored and overwrote saved games | Devin Review on PR #4 | `App` collapsed `null` to `undefined` and the session helpers' default parameters substituted `defaultStorage()` for `undefined` | `null` is carried through to `loadSession`/`saveSession`, which accept `Storage | null | undefined` and skip storage when it is falsy | `session.test.ts` — "does not fall back to localStorage when given null"; `App.test.tsx` — "ignores localStorage when storage is null" |
| Restored partial turns whose moves could not be completed into a legal turn crashed with `IllegalMoveError` when the forfeit timer passed | Devin Review on PR #4 | `deserializeSession` replayed saved moves individually but never checked they were a prefix of a complete turn | Session restore requires `canCompleteTurn(turnStart, turnMoves)`, the same engine-backed check that gates clickable moves | `session.test.ts` — "rejects saved moves that cannot be completed into a legal turn"; `App.test.tsx` — "falls back to the start screen instead of crashing when a saved partial turn cannot be completed" |
